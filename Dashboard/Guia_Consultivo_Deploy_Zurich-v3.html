Análise de Viabilidade Técnica e Alternativas de Deploy

Projeto: Dashboard de Conformidade Zurich Airport  |  Autor: Gabriel Vital (CS Efcaz)  |  Atualizado: 03/06/2026

Status atual do deploy (jun/2026) O servidor Efcaz está inacessível para hospedagem direta (ambiente controlado pela AZ). A alternativa em andamento é o Cenário C — envio por e-mail via N8N. João está investigando erro no nó Execute Command. Cenários A e B permanecem como opções de médio prazo.

1. Contexto Geral

Estruturamos um relatório customizado em formato HTML estático para viabilizar uma visualização gráfica, interativa e executiva para as gestoras da Zurich Airport (Débora e Claudinha). Vale ressaltar que a base de dados do cliente permanece sob total gestão da Efcaz em nosso ambiente em nuvem, garantindo isolamento completo de segurança.

O objetivo deste documento é apresentar e submeter à sua avaliação técnica as três alternativas possíveis para a publicação automatizada deste painel. O Cenário C é a alternativa mais simples e está sendo operacionalizada agora — os Cenários A e B representam evoluções para quando o acesso ao servidor estiver disponível.

2. Cenário A: Hospedagem via Google Cloud Storage (GCS)

Nesta abordagem, o processamento pesado das regras de negócio permanece em nossa infraestrutura. O fluxo realiza apenas um upload de saída do arquivo HTML estático gerado para uma pasta privada na nuvem do Google.

Pré-requisito a confirmar antes de escolher este cenário A autenticação via IAM do Google exige que as usuárias possuam conta Google ativa — preferencialmente via Google Workspace corporativo. Se a Zurich Airport utilizar Microsoft 365 ou outro provedor de e-mail, as gestoras precisariam criar uma conta Google separada para acessar o dashboard, o que aumenta o atrito e reduz o benefício desta abordagem. Sugestão: confirmar com Débora ou Ricardo antes de avançar.

Pontos de Atenção para Alinhamento:

  • Isolamento da Infraestrutura: O banco de dados e o servidor N8N continuam protegidos na nuvem atual da Efcaz. O ambiente externo consome apenas o output visual isolado.
  • Gestão de Identidade Integrada: Elimina a necessidade de criar senhas de forma manual. O próprio Google cuida da autenticação corporativa via conta Workspace das usuárias.
  • Acesso por Domínio: Conseguimos liberar o acesso de forma ilimitada para todos da organização Efcaz com e-mail corporativo, mantendo permissões estritas para os e-mails externos aprovados da Zurich.

Diretrizes Gerais de Configuração:

  1. Criação do Bucket: Criação de bucket privado com controle de acesso unificado e prevenção de acesso público ativada no console de nuvem do Google.
  2. Configuração do IAM (Controle de Acesso): Atribuição do papel de Leitor de Objetos do Storage (Storage Object Viewer) para o domínio interno e para os e-mails das gestoras da Zurich.
  3. Criação de Service Account para o N8N: Geração de uma Service Account no GCP com permissão de escrita no bucket (Storage Object Creator). A chave JSON gerada é configurada como credencial no nó do N8N — etapa necessária para que o fluxo consiga realizar o upload automatizado com segurança.
  4. Automação no Fluxo: Utilização do nó nativo do Google Cloud Storage no N8N. Para o navegador renderizar diretamente em formato de página da web, o arquivo é definido como index.html com Mime Type fixado em text/html.
URL Sugerida para Acesso Final (Cenário A):
https://storage.cloud.google.com/efcaz-zurich-dashboard/index.html

3. Cenário B: Servidor Local com Servidor Web (Nginx)

Caso a nossa arquitetura atual na nuvem tenha restrições ou facilidades operacionais que tornem mais prático servir os arquivos de forma interna pelo nosso próprio servidor web, mapeamos o fluxo tradicional de diretórios estáticos e restrição por rede.

Diretrizes Gerais de Configuração:

  1. Estrutura de Diretório Local: Definição de uma pasta local no servidor e atribuição de permissões de escrita para o serviço do N8N.
  2. Bloco de Configuração Web (Nginx/Apache): Apontamento de rota ou subdomínio dedicado ao relatório, combinando proteção de senha básica para clientes e regras de rede interna. Atenção: a barra final em location /zurich/ é obrigatória para o alias funcionar corretamente — sem ela o nginx não resolve o caminho do arquivo. 
    location /zurich/ {
    alias /srv/static/zurich/;
    index relatorio_fornecedores_zurich.html;

    auth_basic "Acesso Restrito - Dashboard Zurich";
    auth_basic_user_file /etc/nginx/.htpasswd_zurich;

    satisfy any;
    allow 10.0.0.0/8;       # Ranges de IP da Rede Interna / VPN Efcaz
    allow 192.168.0.0/16;
    deny all;
}

4. Cenário C: Entrega por E-mail via N8N (alternativa atual)

Com o servidor Efcaz temporariamente inacessível, o fluxo N8N extrai os CSVs do Metabase, executa o script Python localmente e envia o HTML gerado como anexo por e-mail para Débora e Claudinha. É a solução de menor atrito para viabilizar a entrega imediata, sem dependência de infraestrutura de servidor.

Fluxo N8N — Cenário C:

[Agendador] — 2x por semana (seg e qui, 08h)
    ↓
[5x HTTP Request — API Metabase]
  GET /api/card/{id}/query/csv  → 4 CSVs + XLS fornecedores
    ↓
[Write Binary File × 5]
  Salva CSVs em pasta data/ com nomes fixos
    ↓
[Execute Command]  ← João investigando erro neste nó
  python relatorio_fornecedores_zurich.py
    ↓
[Read Binary File]
  Lê o HTML gerado
    ↓
[Send Email]
  Anexa relatorio_fornecedores_zurich.html
  Para: debora@zurich / claudinha@zurich
Bloqueio atual — nó Execute Command João está investigando o erro retornado pelo nó Execute Command no N8N ao tentar executar o script Python. Enquanto não resolvido, a atualização do dashboard é feita manualmente: exportar os 5 CSVs do Metabase → salvar em data/ → rodar python relatorio_fornecedores_zurich.py → enviar o HTML por e-mail para Débora e Claudinha.

Vantagens do Cenário C:

  • Sem dependência de servidor web ou bucket na nuvem
  • Débora e Claudinha recebem diretamente no e-mail — sem precisar acessar URL
  • O HTML é standalone: abre no navegador sem internet, sem login
  • Transição suave: quando o servidor estiver disponível, basta substituir o nó Send Email pelo nó de upload (Cenário A ou B)

6. Parecer Técnico — Sugestão de Encaminhamento

Com base na situação atual e nas três alternativas mapeadas, seguem as considerações em ordem de prioridade:

Prioridade imediata — Cenário C (E-mail via N8N)

Resolver o erro no nó Execute Command com João é o único bloqueio para ter o fluxo automatizado funcionando já. Quando resolvido, Débora e Claudinha passam a receber o dashboard atualizado diretamente no e-mail — sem precisar de servidor, sem URL, sem login. É a entrega mais rápida e com menor dependência de infraestrutura.

Médio prazo — Cenário A (GCS) ou B (Nginx), conforme disponibilidade do servidor

Quando o servidor Efcaz estiver acessível, o Cenário B (Nginx) é o mais direto de implementar — o passo a passo já está documentado. O Cenário A é mais elegante mas exige confirmar se a Zurich usa Google Workspace. Uma pergunta rápida à Débora — "vocês usam Google ou Microsoft no e-mail corporativo?" — já resolve essa dúvida e define qual caminho priorizar.

Próximo passo imediato: João compartilhar o erro exato do nó Execute Command para diagnóstico e resolução.

Nota de Consulta: O objetivo deste levantamento é puramente consultivo para entendermos o que se encaixa melhor na nossa rotina atual e na topologia da nossa nuvem. Todas as soluções garantem segurança total e isolamento dos dados originais da Efcaz. Fico à disposição para analisarmos qual arquitetura faz mais sentido priorizarmos.
